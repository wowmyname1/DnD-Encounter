# Спецификация D&D Encounter Builder

## Статус

Документ находится в процессе наполнения.

## 1. Обзор

D&D Encounter Builder - одностраничное приложение для проведения боёв D&D 5e. Приложение работает в браузере без сервера и без сборки.

Основной фокус:

- управление персонажами;
- бой и инициатива;
- HP, урон, лечение, временные HP;
- кубики и режимы распределения бросков;
- статусы и триггеры;
- заклинания;
- карта с токенами;
- пользовательские расширения.

## 2. Цели приложения

- Быстро создавать PC и NPC.
- Вести бой с порядком инициативы и раундами.
- Применять урон, лечение и временные HP.
- Бросать кубики с режимами одиночного применения, AoE и разброса.
- Управлять статусами с длительностью и триггерами.
- Использовать карту с токенами и визуальным порядком боя.
- Расширять систему пользовательскими статусами и заклинаниями.
- Держать код модульным без сборщиков и фреймворков.

## 3. Пользовательские роли

### ДМ

- Создаёт NPC.
- Размещает токены на карте.
- Запускает бой и переключает ходы.
- Применяет урон, лечение и статусы.
- Следит за длительностями эффектов.
- Использует каталоги статусов и заклинаний.

### Игрок

- Создаёт или получает PC.
- Бросает кубики.
- Применяет результаты к персонажам.
- Использует заклинания и статусы.
- Следит за HP и эффектами.

## 4. Технологические ограничения

- Без серверной части.
- Без сборщика.
- Только HTML, CSS и vanilla JavaScript.
- Интерфейс должен работать в современном браузере.
- Данные во время сессии хранятся в памяти страницы.
- Сохранение состояния между перезагрузками планируется через localStorage.
- Не используются внешние библиотеки.

## 6. Основные сущности

### Character

Описание персонажа или NPC.

Поля:

- id - уникальный идентификатор.
- type - тип персонажа: pc или npc.
- name - имя.
- cls - класс или тип существа.
- level - уровень.
- ac - класс брони.
- init - бонус инициативы.
- hpMax - максимальные HP.
- hpCur - текущие HP.
- color - цвет персонажа и токена.
- description - описание.
- abilities - характеристики D&D 5e.
- spellAbility - заклинательная характеристика.
- spellSaveDC - сложность спасброска.
- cantripBonus - бонус атаки заговора.
- useHpFormula - использовать ли формулу HP.
- hpBase - базовое HP.
- hpPerLevel - HP за уровень.
- hpConFactor - коэффициент модификатора Телосложения.
- statuses - активные статусы.
- x - координата токена по горизонтали.
- y - координата токена по вертикали.

### Abilities

Характеристики персонажа:

- str - Сила.
- dex - Ловкость.
- con - Телосложение.
- int - Интеллект.
- wis - Мудрость.
- cha - Харизма.

Формула модификатора характеристики:

modifier = floor((score - 10) / 2)

### ActiveRoll

Активный бросок кубиков.

Поля:

- expression - исходное выражение броска.
- dice - список выпавших кубиков.
- modifier - модификатор броска.
- mode - режим применения: single, aoe, spread.
- applyType - тип применения: damage, heal, temp.
- aoeTargets - выбранные цели для AoE.
- maxSelected - максимум одновременно активных кубиков.

### Combat

Состояние боя.

Поля:

- combatActive - активен ли бой.
- turnOrder - порядок инициативы.
- currentTurnIndex - индекс текущего персонажа.
- round - номер раунда.

### Status

Активный статус на персонаже.

Примерные поля:

- id - уникальный идентификатор экземпляра статуса.
- name - название статуса.
- icon - иконка статуса.
- duration - длительность.
- remaining - оставшееся время.
- source - источник статуса.
- logic - логика срабатывания и эффектов.

## 8. Механика персонажей

### Создание персонажа

- Пользователь открывает модальное окно для PC или NPC.
- Заполняются имя, класс, уровень, AC, инициатива и HP.
- Задаются характеристики: Сила, Ловкость, Телосложение, Интеллект, Мудрость, Харизма.
- Можно включить формулу HP.
- Можно выбрать цвет персонажа.
- Можно задать описание.
- Можно указать заклинательную характеристику, сложность спасброска и бонус заговора.

### Формула HP

- Если включена формула HP, максимальные HP считаются автоматически.
- Модификатор Телосложения считается как floor((CON - 10) / 2).
- Для первого уровня используется базовое HP плюс модификатор Телосложения, умноженный на коэффициент.
- Для каждого следующего уровня используется HP за уровень плюс модификатор Телосложения, умноженный на коэффициент.
- Итоговое значение округляется.
- Минимальное значение максимальных HP - 1.

### Редактирование персонажа

- Кнопка редактирования открывает то же модальное окно с уже заполненными полями.
- При сохранении данные персонажа обновляются.
- Если изменился максимум HP, текущие HP не должны превышать новый максимум.
- Редактирование не должно автоматически удалять статусы персонажа.

### Развёрнутая карточка

- Кнопка деталей открывает отдельное модальное окно.
- В деталях показываются характеристики с модификаторами.
- Показываются текущие и максимальные HP.
- Показываются AC и инициатива.
- Показываются настройки формулы HP.
- Показывается описание персонажа.

### Каталог пресетов

- Пользователь может открыть каталог заранее созданных персонажей.
- Пресет создаёт нового персонажа с заранее заданными параметрами.
- Пресеты могут быть как PC, так и NPC.
- Пресет должен корректно создавать персонажа без ручного заполнения формы.

## 9. Механика боя

### Начало боя

- Бой начинается отдельной кнопкой.
- Для всех персонажей рассчитывается инициатива.
- Персонажи сортируются по инициативе.
- Определяется первый активный персонаж.
- Номер раунда устанавливается в 1.

### Порядок ходов

- Текущий персонаж отображается в интерфейсе.
- Кнопка следующего хода передаёт ход.
- Перед передачей хода обрабатываются эффекты конца хода текущего персонажа.
- После передачи хода обрабатываются эффекты начала хода нового персонажа.

### Раунды

- Когда список инициативы пройден, номер раунда увеличивается.
- Мёртвые персонажи могут исключаться из порядка боя.
- Если живых участников не осталось, бой может быть автоматически сброшен.

### События боя

- turn:end - событие конца хода текущего персонажа.
- turn:start - событие начала хода нового персонажа.
- Эти события используются статусами, триггерами и расширениями.

### Сброс боя

- Сброс боя останавливает боевой режим.
- Очищается порядок инициативы.
- Сбрасывается текущий индекс хода.
- Сбрасывается номер раунда.
- Интерфейс возвращается в небоевой режим.

## 10. Карта и токены

### Токены

- Каждый персонаж имеет токен на карте.
- Цвет токена соответствует цвету персонажа.
- Токен можно перетаскивать мышью.

### Координаты

- Позиция токена хранится в полях x и y персонажа.
- Координаты ограничиваются границами карты.

### Взаимодействие

- Клик по токену может применять активный бросок в зависимости от режима.
- В режиме single активная сумма применяется к персонажу.
- В режиме spread применяется один выбранный кубик.
- В режиме aoe клик может добавлять или убирать персонажа из списка целей.

### Отображение боя

- Активный персонаж может подсвечиваться.
- Порядок инициативы отображается отдельным списком.
- HP и статусы персонажа отражаются в карточке.

## 11. Механика кубиков

### Поддерживаемые выражения

Приложение должно поддерживать основные выражения бросков D&D:

- Один кубик, например 1d20.
- Несколько кубиков, например 3d6.
- Модификаторы, например 1d20 + 5 или 2d8 - 2.
- Несколько групп кубиков, например 2d6 + 1d4 + 3.
- Выбор лучших кубиков: kh, например 4d6kh3.
- Выбор худших кубиков: kl, например 2d20kl1.

### Парсер бросков

- Выражение проверяется перед броском.
- Парсер разбирает количество кубиков, грани и модификаторы.
- Для kh и kl парсер определяет, какие кубики остаются активными.
- Отрицательные модификаторы должны учитываться в итоговой сумме.

### Результат броска

- После броска создается активный бросок.
- Каждый кубик отображается в лотке.
- Пользователь может видеть значение каждого кубика.
- Активные кубики участвуют в сумме.
- Неактивные кубики не участвуют в сумме, но остаются видимыми.

### Повторное использование кубиков

- Использованные кубики не должны становиться полностью недоступными.
- Использованный кубик просто перестает быть активным.
- Пользователь может снова сделать кубик активным, если это допустимо режимом.
- Активный бросок не должен автоматически удаляться после первого применения, если остались доступные кубики.

### Ограничение количества активных кубиков

- Для обычных бросков активными могут быть все кубики.
- Для бросков с kh или kl активным должно оставаться выбранное количество кубиков.
- Пример: 3d6kh2 показывает три результата, но активными остаются два наибольших.
- Пользователь может менять выбор, если количество активных кубиков не превышает допустимое.

### Режимы применения

#### Одиночный режим

- Все активные кубики применяются к одной цели.
- Цель выбирается кликом по HP-бару карточки или по токену на карте.
- Тип применения определяется текущей кнопкой: урон, лечение или временные HP.

#### AoE режим

- Пользователь выбирает несколько целей.
- Цели можно выбирать кликами по HP-барам карточек.
- Цели можно выбирать кликами по токенам на карте.
- В будущем должен поддерживаться выбор радиусом на карте.
- Применение происходит отдельной кнопкой.
- Кнопка применения должна отражать текущий тип: урон, лечение или временные HP.

#### Разброс

- За одно нажатие по цели применяется один активный кубик.
- Кубики применяются по порядку, слева направо.
- После применения кубик становится неактивным.
- Пользователь может снова активировать кубик при необходимости.
- Режим подходит для распределения нескольких бросков между разными целями.

### Типы применения

- Урон: уменьшает текущие HP цели.
- Лечение: восстанавливает текущие HP цели.
- Временные HP: добавляет временный буфер здоровья.

### Индикация применения

- При наведении на HP-бар должно показываться превью результата.
- Превью должно учитывать режим применения.
- Превью должно учитывать тип применения: урон, лечение или временные HP.
- Для AoE превью должно показывать сумму, которая будет применена к выбранным целям.
- Для разброса превью должно показывать значение следующего активного кубика.

## 12. Механика HP

### Основные поля

- hpMax - максимальные HP персонажа.
- hpCur - текущие HP персонажа.
- Для временных HP используется отдельное состояние или отдельное поле персонажа.

### Урон

- Урон уменьшает текущие HP персонажа.
- Если у персонажа есть временные HP, сначала уменьшается буфер временных HP.
- Если временных HP недостаточно, оставшийся урон применяется к текущим HP.
- Текущие HP не должны становиться меньше нуля.

### Лечение

- Лечение увеличивает текущие HP персонажа.
- Текущие HP не должны превышать максимальные HP.
- Лечение не должно автоматически убирать статусы.

### Временные HP

- Временные HP используются как буфер против урона.
- Временные HP не суммируются бесконечно, если правилами выбрано ограничение.
- Временные HP не лечат персонажа напрямую.
- Временные HP отображаются отдельно или визуально отличаются от обычных HP.

### Отображение HP

- Карточка персонажа показывает текущие и максимальные HP.
- HP-бар визуально отражает состояние персонажа.
- Изменения HP могут сопровождаться плавающим текстом.
- Цвет плавающего текста зависит от типа изменения: урон, лечение, временные HP.

### Взаимодействие с HP

- Пользователь может менять HP через кубики.
- Пользователь может менять HP через быстрые действия карточки.
- Пользователь может вручную ввести значение HP через редактирование.
- Применение кубиков не должно требовать отдельное всплывающее окно для выбора типа действия, если тип уже выбран в панели режимов.

### Смерть персонажа

- Если текущие HP равны нулю, персонаж считается побежденным или находящимся без сознания.
- Дальнейшая интерпретация состояния при нулевых HP остается на усмотрение ДМ.
- Приложение должно визуально показывать, что персонаж имеет нулевые HP.

## 13. Механика статусов

### Назначение статусов

Статусы нужны для отслеживания эффектов, которые действуют на персонажа в течение боя или сцены. Статусы могут быть полезными, вредными или нейтральными.

Примеры эффектов:

- баффы;
- дебаффы;
- периодический урон;
- периодическое лечение;
- временные HP;
- ограничения действий;
- бонусы к защите или атаке.

### Типы статусов

#### Встроенные статусы

- Приложение содержит базовый каталог статусов.
- Такие статусы можно быстро добавить персонажу.
- Встроенные статусы могут использоваться как примеры для пользовательских эффектов.

#### Пользовательские статусы

- Пользователь может создавать собственные статусы.
- Пользовательские статусы настраиваются через конструктор.
- Пользовательские статусы сохраняются локально.
- Пользовательские статусы можно редактировать и удалять.

#### Постоянные статусы

- Постоянные статусы действуют до ручного снятия.
- Такие статусы не имеют автоматически истекающей длительности.
- Они подходят для эффектов, которые действуют до конца сцены или до снятия.

#### Временные статусы

- Временные статусы имеют длительность.
- Длительность может измеряться раундами или ходами.
- Когда длительность заканчивается, статус снимается автоматически.

### Экземпляр статуса

Активный статус на персонаже должен содержать:

- уникальный идентификатор экземпляра;
- название статуса;
- иконку;
- длительность;
- оставшееся время;
- источник статуса;
- логику срабатывания;
- дополнительные параметры, если они нужны для эффекта.

### Длительность статусов

- Постоянные статусы не уменьшаются автоматически.
- Временные статусы уменьшаются в подходящий момент боя.
- Момент уменьшения длительности зависит от настройки статуса.
- Если длительность достигла нуля, статус должен быть снят.
- Снятие статуса по истечении длительности должно происходить без участия пользователя.

### Триггеры статусов

Статусы могут срабатывать по событиям боя.

Основные триггеры:

- начало хода персонажа;
- конец хода персонажа;
- получение урона персонажем.

Дополнительные триггеры в будущем:

- добавление статуса;
- снятие статуса;
- лечение персонажа;
- получение временных HP;
- применение заклинания;
- ручной вызов эффекта.

### Логика статуса

Логика статуса строится из узлов.

Узел может быть:

- триггером;
- условием;
- действием.

#### Триггер

Триггер определяет, в какой момент активируется логика статуса.

Примеры:

- в начале хода персонажа;
- в конце хода персонажа;
- когда персонаж получает урон.

#### Условие

Условие проверяет состояние персонажа или боя перед выполнением действия.

Примеры условий:

- у персонажа меньше половины HP;
- у персонажа есть другой статус;
- персонаж является активным участником боя;
- персонаж жив;
- бросок прошел успешно;
- бросок провалился.

#### Действие

Действие изменяет состояние игры.

Примеры действий:

- нанести урон;
- вылечить персонажа;
- добавить временные HP;
- добавить другой статус;
- снять статус;
- показать сообщение;
- изменить параметр персонажа.

### Защита от рекурсии

Исполнение статусов не должно вызывать бесконечные цепочки срабатываний.

Для этого используется защитный механизм:

- при входе в исполнение триггера устанавливается глобальный флаг;
- пока флаг установлен, вложенные исполнения могут игнорироваться;
- после завершения исполнения флаг снимается.

Это предотвращает ситуации, когда статус наносит урон, урон вызывает триггер, триггер снова наносит урон, и цикл повторяется бесконечно.

### Отображение статусов

Активные статусы должны быть видны в карточке персонажа.

Каждый статус может показывать:

- иконку;
- название;
- оставшуюся длительность;
- источник эффекта;
- краткое описание.

Пользователь должен иметь возможность:

- посмотреть активные статусы персонажа;
- снять статус вручную, если это разрешено;
- добавить новый статус из каталога;
- открыть конструктор статусов.

### Каталоги статусов

Приложение поддерживает каталоги статусов.

Каталог позволяет:

- просматривать доступные статусы;
- добавлять статусы персонажу;
- редактировать пользовательские статусы;
- удалять пользовательские статусы;
- сохранять пользовательские статусы локально.

### Примеры статусов

#### Регенерация

- Триггер: начало хода персонажа.
- Действие: восстановить несколько HP.
- Длительность: несколько раундов.

#### Яд

- Триггер: начало или конец хода персонажа.
- Действие: нанести урон.
- Длительность: несколько раундов.

#### Благословение

- Триггер: не обязателен.
- Действие: положительный эффект на броски или защиту.
- Длительность: ограниченное время.

#### Щит

- Триггер: получение урона.
- Действие: уменьшить урон или добавить временные HP.
- Длительность: до снятия или до истечения времени.

#### Оглушение

- Триггер: начало хода персонажа.
- Действие: показать сообщение или ограничить действия.
- Длительность: один или несколько ходов.

## 14. Механика заклинаний

### Назначение заклинаний

Заклинания позволяют персонажам применять особые эффекты к целям:

- урон;
- лечение;
- временные HP;
- добавление статусов;
- снятие статусов;
- баффы и дебаффы;
- специальные эффекты.

### Текущее состояние системы заклинаний

Сейчас заклинания реализованы как отдельная система расширений.

Они имеют:

- каталог заклинаний;
- конструктор пользовательских заклинаний;
- механизм выбора целей;
- собственный процесс применения эффектов.

В будущем систему заклинаний планируется сильнее связать с системой статусов и кубиков, чтобы уменьшить количество отдельной жестко заданной логики.

### Объект заклинания

Заклинание может содержать:

- уникальный идентификатор;
- название;
- иконку;
- описание;
- режим выбора целей;
- логику применения;
- параметры спасброска, если заклинание требует спасброска;
- бонус атаки, если заклинание использует атаку;
- пользовательские данные.

### Режимы выбора целей

#### Одиночная цель

Заклинание применяется к одному персонажу.

Порядок работы:

1. Пользователь выбирает заклинание.
2. Переходит в режим выбора цели.
3. Кликает по карточке или токену персонажа.
4. Цель сохраняется.
5. Пользователь применяет заклинание.

#### Несколько целей

Заклинание применяется к группе персонажей.

Порядок работы:

1. Пользователь выбирает заклинание.
2. Переходит в режим выбора целей.
3. Отмечает нужных персонажей.
4. Видит список или количество выбранных целей.
5. Применяет заклинание ко всем выбранным целям.

#### Распределение по целям

Заклинание может распределяться по целям по одному эффекту за клик.

Порядок работы:

1. Пользователь выбирает заклинание.
2. Переходит в режим распределения.
3. Кликает по целям по очереди.
4. Каждый клик применяет часть эффекта.
5. Когда эффект закончился, применение завершается.

### Активное состояние заклинания

Во время применения заклинания приложение хранит активное состояние:

- выбранное заклинание;
- режим выбора целей;
- список выбранных целей;
- последнюю выбранную цель;
- признак того, что идет выбор целей.

### Применение заклинания

После выбора целей заклинание применяется к целям.

Эффект может:

- наносить урон;
- лечить персонажа;
- добавлять временные HP;
- накладывать статус;
- снимать статус;
- показывать сообщение;
- комбинировать несколько действий.

Результат применения должен быть понятен пользователю:

- через изменение HP;
- через изменение статусов;
- через плавающий текст;
- через сообщения в интерфейсе.

### Конструктор заклинаний

Пользователь может создавать собственные заклинания.

Конструктор должен позволять задать:

- название заклинания;
- иконку;
- описание;
- режим выбора целей;
- эффект;
- длительность эффекта, если эффект является статусом;
- дополнительные параметры.

Сложные заклинания могут настраиваться через узлы логики:

- триггер;
- условие;
- действие.

### Будущее развитие системы заклинаний

Заклинания должны постепенно перейти на общую архитектуру статусов и кубиков.

Желаемое направление:

- заклинание может накладывать статус;
- статус может содержать логику эффекта;
- заклинание может использовать броски кубиков;
- урон заклинания должен проходить через общую систему урона;
- лечение заклинания должно проходить через общую систему HP;
- заклинания могут генерировать события для других систем.

Это позволит сделать заклинания расширяемыми и уменьшить дублирование логики между статусами и заклинаниями.

## 15. Событийная модель

### Назначение событийной модели

Событийная модель нужна для слабой связанности модулей. Модули не обязаны знать друг о друге напрямую. Они могут реагировать на события.

### Шина событий

В приложении используется общая шина событий AppEvents.

Она поддерживает:

- подписку на событие;
- отписку от события;
- генерацию события;
- передачу данных вместе с событием.

### Текущие события

#### turn:start

Событие начала хода персонажа.

Используется для:

- эффектов начала хода;
- статусов с триггером начала хода;
- визуальной подсветки активного персонажа.

#### turn:end

Событие конца хода персонажа.

Используется для:

- эффектов конца хода;
- статусов с триггером конца хода;
- уменьшения длительностей.

#### damage:taken

Событие получения урона персонажем.

Используется для:

- статусов с триггером получения урона;
- реакций на урон;
- будущих счетчиков и эффектов.

### Будущие события

#### heal:received

Персонаж получил лечение.

#### temp:applied

Персонаж получил временные HP.

#### status:applied

На персонажа был добавлен статус.

#### status:removed

С персонажа был снят статус.

#### spell:cast

Было применено заклинание.

#### combat:start

Бой начался.

#### combat:end

Бой закончился.

#### character:created

Персонаж был создан.

#### character:updated

Персонаж был изменен.

#### character:removed

Персонаж был удален.

### Полезная нагрузка событий

Событие должно передавать контекст.

Примеры данных:

- идентификатор персонажа;
- значение урона;
- значение лечения;
- источник эффекта;
- идентификатор статуса;
- идентификатор заклинания;
- дополнительные параметры эффекта.

### Подписки на события

- Расширения подписываются на события при инициализации.
- Статусы используют события для срабатывания триггеров.
- Интерфейс может использовать события для обновления отображения.
- Будущие модули могут использовать события без изменения существующих модулей.

### Защита от рекурсии

События не должны вызывать бесконечные цепочки.

Пример опасной цепочки:

1. Урон вызывает событие damage:taken.
2. Статус реагирует на damage:taken.
3. Статус наносит новый урон.
4. Новый урон снова вызывает damage:taken.
5. Цикл повторяется.

Для защиты используется флаг window.__inTrigger.

Пока выполняется один триггер, вложенные исполнения могут игнорироваться.

### Пример потока событий при передаче хода

1. Пользователь нажимает следующий ход.
2. Боевой модуль генерирует событие turn:end для текущего персонажа.
3. Статусы с триггером конца хода исполняют свои эффекты.
4. Боевой модуль переключает ход.
5. Боевой модуль генерирует событие turn:start для нового персонажа.
6. Статусы с триггером начала хода исполняют свои эффекты.
7. Интерфейс обновляет активного персонажа.

## 16. Пользовательские данные и сохранение

### Текущее состояние

Во время работы приложение хранит данные в памяти страницы. Персонажи, токены, бой, статусы и настройки могут теряться после перезагрузки.

### Планируемое сохранение

Для сохранения состояния должен использоваться localStorage.

Сохраняться могут:

- персонажи;
- позиции токенов;
- текущий бой;
- порядок инициативы;
- номер раунда;
- активные статусы;
- пользовательские статусы;
- пользовательские заклинания;
- настройки формул HP;
- выбранные цвета;
- сохраненные броски, если эта функция используется.

### Автосохранение

- Изменения могут сохраняться автоматически.
- Сохранение должно быть неблокирующим.
- Ошибки localStorage не должны ломать приложение.

### Загрузка состояния

- При загрузке страницы приложение должно восстанавливать состояние.
- Если данных нет, приложение запускается в чистом состоянии.
- Если данные повреждены, приложение должно начать чистую сессию.

### Экспорт и импорт

В будущем можно добавить экспорт и импорт партии в JSON:

- экспорт текущего состояния;
- импорт состояния;
- перенос партии между браузерами;
- резервное копирование компании.

## 17. Интерфейс и UX

### Общие принципы

- Интерфейс должен быть понятен ДМ и игрокам.
- Основные действия должны быть видны без глубоких меню.
- Опасные действия должны быть заметны.
- Состояние персонажа должно читаться с первого взгляда.

### Карточка персонажа

Карточка должна показывать:

- имя;
- класс или тип;
- уровень;
- AC;
- HP;
- статусы;
- цвет персонажа;
- быстрые действия.

### Быстрые действия

Быстрые действия карточки:

- редактирование;
- детали;
- изменение HP;
- временные HP;
- статусы;
- быстрые броски;
- удаление.

### Панель кубиков

Панель кубиков должна показывать:

- поле ввода выражения;
- кнопки популярных кубиков;
- результат броска;
- лоток выпавших кубиков;
- режимы применения;
- тип применения;
- активную сумму.

### Карта

Карта должна показывать:

- токены персонажей;
- активный токен;
- выбранные цели;
- перетаскивание токенов;
- будущий выбор AoE радиусом.

### Модальные окна

Модальные окна должны:

- открываться быстро;
- закрываться кнопкой;
- не терять введенные данные случайно;
- иметь понятные заголовки.

### Пресеты

Каталог пресетов должен позволять:

- быстро добавлять типовых персонажей;
- видеть краткую информацию о пресете;
- добавлять пресет одним кликом.

### Ошибки и сообщения

- Приложение должно показывать короткие понятные сообщения.
- Ошибки ввода должны объяснять проблему.
- Критические ошибки не должны ломать весь интерфейс.

## 18. Тестирование

### Smoke-тест структуры

В проекте есть базовый smoke-тест.

Он проверяет:

- наличие основных файлов;
- наличие основных скриптов в index.html;
- наличие ключевых функций и модулей;
- отсутствие грубых нарушений структуры.

### Ручное тестирование

Основные ручные проверки:

- создание персонажа;
- редактирование персонажа;
- удаление персонажа;
- создание из пресета;
- бой и инициатива;
- применение урона;
- лечение;
- временные HP;
- кубики single, aoe, spread;
- статусы;
- триггеры;
- конструктор статусов;
- конструктор заклинаний;
- сохранение состояния после появления localStorage.

### Граничные случаи

- пустое имя персонажа;
- отрицательные значения;
- нулевые HP;
- отсутствие целей;
- бросок без активных кубиков;
- все кубики использованы;
- статус с нулевой длительностью;
- поврежденные локальные данные;
- одновременное срабатывание нескольких триггеров.
